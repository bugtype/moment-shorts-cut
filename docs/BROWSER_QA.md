## 프레임 간격 수정과 제한

기존 코드는 매번 마지막 그리기 시간을 현재 시각으로 바꾸면서 남은 시간을 버렸습니다. 60 Hz 입력을 2초간 모의 실행했을 때 42회만 그리는 문제를 재현했습니다. 남은 시간을 유지하도록 수정했고 `tests/app-media.test.mjs`에서 목표 60회(±1)를 확인합니다.

브라우저 MediaRecorder 출력은 여전히 기기·디코더·화면 부하의 영향을 받는 가변 프레임 레이트입니다. 최종 4초 테스트 MP4의 평균은 약 **21.7 fps**였습니다. 고정 30 fps 인코딩이나 실시간 성능을 보장하지 않으며, 이 결과를 숨기지 않습니다. 프레임 간격 수정이 하드웨어 코덱·시작 지연을 해결했다는 뜻도 아닙니다.

## 재현 방법

앱을 실행한 뒤 별도 터미널에서 테스트 원본을 만듭니다. FFmpeg는 이 수동 점검에만 필요하며 앱 실행·`npm test`의 의존성이 아닙니다.

```sh
ffmpeg -f lavfi -i testsrc2=size=640x360:rate=30 \
  -f lavfi -i sine=frequency=440:sample_rate=48000 \
  -t 4 -c:v libx264 -pix_fmt yuv420p -c:a aac moment-test.mp4
```

다음 내용을 UTF-8 `captions.srt`로 저장합니다.

```srt
1
00:00:00,000 --> 00:00:02,000
첫 번째 자막
두 번째 줄

2
00:00:02,000 --> 00:00:04,000
마지막 장면 🌊
```

1. 데스크톱 브라우저에서 영상을 업로드하고 자막 탭에서 SRT를 불러옵니다.
2. 저장하고 새로고침한 뒤 영상·자막을 확인합니다.
3. MP4/H.264·720p로 내보냅니다. 탭을 계속 활성 상태로 둡니다.
4. 원본과 다른 경로에 결과를 저장하고 별도 플레이어로 끝까지 재생합니다.
5. `ffprobe`와 디코더로 컨테이너·영상·오디오를 확인합니다. 가변 프레임 레이트를 그대로 검사하도록 time base를 유지합니다.

```sh
ffprobe -v error -show_entries format=duration,size:stream=codec_name,codec_type,width,height,avg_frame_rate -of json output.mp4
ffmpeg -v error -i output.mp4 -map 0:v:0 -c:v rawvideo -fps_mode passthrough -enc_time_base demux -f null -
ffmpeg -v error -i output.mp4 -map 0:a:0 -f null -
```

| 별도 확인이 필요한 영역 | 이 기록에 포함되지 않은 것 |
|---|---|
| 녹음·음성 인식 | 실제 마이크 권한·녹음, 모델 다운로드, 한국어 정확도 |
| 브라우저·기기 | Safari/Firefox, 모바일 실기기 |

테스트 영상의 오디오는 사인파이므로 음성 인식 평가 자료가 아닙니다. 스크린샷과 영상에는 개인 미디어를 사용하지 않았습니다.

## 대화상자 이름과 가져오기 오류 · 보조 기술 확인 대기

공용 대화상자는 `aria-labelledby`로 현재 보이는 번역 제목을 참조하며, 출력 준비·진행·완료 화면도 같은 참조를 유지합니다. 코드·모의 DOM 검사는 제목 연결과 세 언어 문구를 확인하지만, 실제 접근성 트리나 화면 읽기 프로그램의 알림은 검증하지 않았습니다.

- 한국어·영어·중국어에서 파일·템플릿·자막 대화상자의 이름과 닫기 후 초점을 확인하세요.
- 출력 준비·진행·완료 및 열린 창의 언어 변경에서 현재 제목이 올바르게 전달되는지 확인하세요.
- 잘못된 JSON 설정·템플릿 파일은 원문 조각 대신 번역된 오류를 표시해야 합니다. 오류 중 언어를 바꾼 뒤 정상 파일로 재시도하고 기존 내용이 보존되는지 확인하세요.

사용합니다. 실제 미디어 탐색·렌더링 결과는 별도 브라우저 확인이 필요합니다.

수정 키와 실제 포인터 이동의 결합은 모의 DOM 검사를 통과해도 별도 하드웨어/브라우저 점검이 필요합니다.


## 프로젝트 이름 초안 · 수동 확인 대기

**실제 브라우저의 IME 조합·커서/선택·blur/change·비동기 오디오 준비 완료 시점은 아직 검증하지 않았습니다.**

| 수동 점검 | 기대 동작 |
|---|---|
| 오디오 준비를 시작한 뒤 상단 프로젝트 이름을 입력하고 완료 대기 | 같은 프로젝트/저장 이름의 상태 전용 검사기 갱신은 초안·커서·선택·IME 입력을 덮어쓰지 않음; 준비 완료를 새 이름 저장으로 해석하지 않음 |
| 공백 포함/빈 이름을 입력하고 입력란 벗어나기 | 허용된 기존 change 편집에서 앞뒤 공백 제거/현재 언어의 기본 이름 반영; 글자마다 저장하거나 기록하지 않음 |
| 모델 이름 변경·같은 이름의 프로젝트 교체·불러오기·초기화·실행 취소/다시 실행 | 기존 프로젝트/모델 동기화 유지; 다른 프로젝트 문맥이나 공유 명령의 프로젝트 교체까지 초안을 보존한다고 설명하지 않음 |
| 반영 전 설정 백업·브라우저 저장·기존 복구 차단 | 초안 자체는 저장/백업 대상 아님; 버튼 클릭에 앞선 기존 blur/change 반영과 구별, 편집/기록/저장 보호 유지 |

보존 범위는 현재 프로젝트 이름 입력의 상태 전용 갱신입니다. 다른 입력란 전체나
프로젝트 교체 후 초안 보존·새 IME 동작·자동 저장 기능으로 확대해 설명하지 마세요.


## 사용자 템플릿 관리 성공 후 초점 · 수동 확인 대기

**실제 브라우저의 네이티브 대화상자 닫기·키보드 초점·스크린 리더 알림·좁은 화면 배치는 아직 검증하지 않았습니다.**

| 수동 점검 | 기대 동작 |
|---|---|
| 사용자 템플릿 저장·복제·이름 변경·업데이트 성공 | 현재 갤러리에 새로 표시된 해당 템플릿 이름 버튼으로 초점; 제거된 이전 버튼에 초점을 남기지 않음 |
| 삭제 성공·이름 변경 후 현재 필터와 불일치 | 현재 템플릿 검색 입력으로 초점; 숨겨진 카드나 관련 없는 카드로 이동하지 않음 |
| 저장 실패 후 수정/재시도 | 창을 유지하고 바깥으로 초점을 옮기지 않음; 성공한 경우에만 결과 갤러리로 이동 |
| 닫는 중 갤러리/검색/카테고리 교체 또는 새 창 열림 | 이전 갤러리의 결과 요청이 교체 화면이나 새 대화상자에서 초점을 빼앗지 않음 |
| 취소·동일 이름 확인·파일 가져오기 | 기존 닫기/초점 동작 유지; 이번 성공 경로 수정이 모든 대화상자 종료를 바꾼다고 설명하지 않음 |
| 항목이 많은 갤러리·아래쪽 카드·새 복제 항목 | 기본 초점 스크롤을 억제하지 않음; 결과가 화면에 보이는지와 스크롤 위치를 실제 확인 |
| 한·영·중·Tab/Shift+Tab·스크린 리더·좁은 화면 | 새 이름/검색 대상의 초점 표시·접근·알림과 다음 키보드 이동을 실제로 확인 |

검증 범위는 성공한 사용자 템플릿 관리 후의 논리적 초점 대상입니다. 모의 DOM 결과만으로
네이티브 포커스 복귀·전체 대화상자 접근성·보조기술 호환이나 규격 준수를 주장하지 마세요.


## 추가 오디오 완료와 관련 없는 패널 입력 · 수동 확인 대기

**실제 브라우저의 미디어 메타데이터/디코딩·IME·커서/초점·좁은 화면 배치는 아직 검증하지 않았습니다.**

| 수동 점검 | 기대 동작 |
|---|---|
| 느린 오디오 메타데이터 대기 중 타이틀로 이동해 시작값 2.75 입력 후 완료 | 성공 완료 처리만으로 현재 패널을 다시 만들거나 미반영 값을 모델 값으로 덮어쓰지 않음; 실제 커서/선택/IME 동작 별도 확인 |
| 대기 중 타이틀·연출·템플릿·화면 사이 패널 전환 | 시작 시점이 아닌 완료 시점의 현재 패널에만 갱신 여부 적용; 패널 이동 자체의 기존 초안 처리까지 보존한다고 설명하지 않음 |
| 완료 시 오디오·자막·미디어 패널 | 새 오디오 자산/조절부 및 자막 인식 소스 선택 가능 상태를 기존처럼 갱신 |
| 실패·같은 파일 재선택·재시도 | 기존 오류/재시도 동작 유지; 성공 시점의 불필요한 갱신 생략을 실패 복구나 새 미디어 소유권 규칙으로 확대하지 않음 |
| 일시 정지·타임라인/검사기·실행 취소·프로젝트 교체 | 기존 일시 정지/다른 화면 갱신 유지; 대기 중 실행 취소·프로젝트 교체를 넘는 초안 보존이나 새 충돌 차단 보장 없음 |
| 한·영·중·키보드·좁은 화면 | 현재 비의존 패널의 입력/초점과 의존 패널의 새 소스 표시를 실제 확인; 초안이 자동 저장/백업되었다고 설명하지 않음 |

이 범위는 추가 오디오 불러오기 성공 후의 현재 패널 갱신입니다. 모든 입력의 초안 캐시,
자동 저장, 실제 디코딩/재생 품질 또는 텍스트 파일 가져오기의 충돌 정책 변경이 아닙니다.


## 타임라인 클립 키보드 선택 · 수동 확인 대기

**실제 브라우저의 Enter/Space 활성화·초점·스크린 리더·가로 스크롤·터치 동작은 아직 검증하지 않았습니다.**

| 수동 점검 | 기대 동작 |
|---|---|
| Tab으로 다른 영상 클립 버튼에 초점을 두고 Enter/Space | 해당 클립을 선택하고 일시 정지한 뒤 그 등장 구간 시작으로 이동; 선택만 바뀌면 버튼을 제거하지 않고 초점을 유지 |
| 2/4/8배 확대·가로 스크롤·왼쪽이 화면 밖인 클립 | 같은 클립의 키보드 활성화 목적지는 스크롤과 무관; 실제 초점 표시와 다음 Tab/Shift+Tab 이동 확인 |
| 반복/재배열된 원본 구간·배속 변경 | 원본 시작값이 아닌 선택한 등장의 배속 전 타임라인 시작으로 탐색; 출력 시간 표시는 배속 반영 |
| 마우스/터치로 클립 안의 여러 위치 선택 | 기존 좌표 비율 탐색과 선택/검사기 갱신 유지; 터치 스크롤과 탭 활성화를 실제 기기에서 구분 |
| 같은 클립 반복 활성화·상단 프로젝트 이름에 초점을 둔 프로그램 호출 | 좌표 없는 `detail=0` 클릭은 구간 시작으로 이동하며, 선택 갱신이 유지되는 상단 입력의 초점을 빼앗지 않음 |
| 선택 전후 설정·기록·저장소 비교 | 선택 자체는 프로젝트·실행 취소/다시 실행·저장소를 바꾸지 않음; 다른 입력의 기존 blur/change 반영과 구별 |
| 클립 내용/시간·썸네일 변경·한/영/중·좁은 화면 | 실제 내용 갱신은 유지; 이때까지 버튼/초안 보존을 보장하지 않음, 번역된 클립 이름과 초점 표시 확인 |

검증 대상은 기존 클립 버튼의 선택 전용 갱신과 좌표 없는 활성화입니다. `detail=0`은
물리 키보드만을 뜻하지 않으며 `HTMLElement.click()` 같은 프로그램 활성화도 포함합니다.
모의 DOM 검사는 네이티브 키보드·접근성·실제 스크롤 배치나 프레임 정확도의 증명이 아닙니다.


## 템플릿 파일 가져오기 완료와 다른 패널 입력 · 수동 확인 대기

**실제 브라우저의 파일 선택/읽기·IME·커서/초점·스크린 리더·좁은 화면은 아직 검증하지 않았습니다.**

| 수동 점검 | 기대 동작 |
|---|---|
| 개별/모음 템플릿 파일을 읽는 동안 다른 패널로 이동해 미반영 값 입력 | 가져오기 성공 완료가 현재 패널을 다시 만들거나 초안을 지우지 않음; 라이브러리에는 검증된 새 사본 저장 |
| 완료 시 템플릿 패널 열림 / 다른 패널에 머물다가 다시 템플릿 열기 | 현재 템플릿 화면만 즉시 갱신; 나중에 돌아와도 갱신된 라이브러리 조회, 내 템플릿 카테고리와 기존 검색어 처리 유지 |
| 읽는 동안 프로젝트·패널 변경 | 변경 자체만으로 라이브러리 가져오기를 취소하지 않음; 현재 프로젝트에 템플릿을 적용하거나 프로젝트 기록을 만들지 않음 |
| 연속 파일 선택·빈 모음·검증 오류·20개 한도·저장 실패·재시도 | 기존 최신 요청·검증·원자적 추가·실패 시 라이브러리 보존 유지; 화면 갱신 생략을 새 저장/복구 정책으로 해석하지 않음 |

이 변경은 템플릿 라이브러리 화면 갱신 범위만 제한하며 초안 캐시·자동 저장을 추가하거나
프로젝트 설정/SRT/VTT 파일의 대기 중 충돌 보호를 바꾸지 않습니다.
